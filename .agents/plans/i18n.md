# План: full internationalization для Rain

Статус: реализован; full check green
Дата анализа: 2026-09-17
Целевой репозиторий: Rain
Исходник функциональных требований: `../../vv/framework/i18n`

## 1. Резюме

Rain добавляет полный optional i18n bounded context. Это не `ResourceBundle` с mutable process-default locale и не несколько `messages_ru.properties`: одна декларация каталога компилируется в immutable, content-addressed snapshot; typed deferred message рендерится только через явно выбранный locale/formatting/time-zone view; release, review, tenant overlay, public export и durable delivery имеют проверяемые contracts.

Новые publishable modules:

1. `rain-i18n` — pure Kotlin kernel: source/artifact codecs, `rain-mf2/v1` parser/compiler, catalog, locale policy, typed message/value contracts, rendering, direct formatters, overlays и in-process controller.
2. `rain-i18n-test` — deterministic formatter/reference fixtures, catalogue/overlay/controller conformance, fuzz-like generators и golden helpers.
3. `rain-i18n-observability` — отдельный pairwise bridge: closed low-cardinality `I18nObserver` → Micrometer/Rain observability; no request/tenant/catalog labels.
4. `rain-i18n-tool` — Gradle-integrated CLI/library: check, extract, merge, review, pseudo, compile, generate-kotlin, export-typescript и verified publication.
5. `rain-i18n-web` — servlet/MVC bridge, scoped `I18nRuntime`, Spring `LocaleContextResolver` compatibility and localized RFC 9457 adapter.
6. `rain-i18n-jobs` — exact current-or-pinned i18n context for durable jobs/outbox and retention contracts.
7. `rain-i18n-persistence` — optional JDBC/jOOQ store for published artifacts, release heads, bounded retained snapshots and durable pins.
8. `rain-tenancy-i18n` — единственный adapter между tenancy и i18n: tenant default locale/time zone and reviewed tenant overlays. Базовые `rain-tenancy` и `rain-i18n` не зависят друг от друга.
9. `rain-i18n-integration` — explicit SPI, wire contracts and deterministic in-memory conformance adapters for TMS, remote catalog release exchange, browser-client contracts and tenant-admin commands; no vendor/client framework dependency leaks into the kernel.

`rain-i18n` использует pinned ICU4J для Unicode/CLDR data and low-level formatting. Публичный grammar engine не использует ICU4J `message2.MessageFormatter`: его API draft/technology-preview, поэтому stable profile, AST and all validation are Rain-owned. Если появится совместимый ICU MF2 adapter, он допускается только за тем же profile-conformance suite и с новой engine identity; он не меняет интерпретацию существующего artifact.

## 2. Полный функциональный scope

GA содержит весь функциональный контур VV, адаптированный к Kotlin/Spring:

- strict canonical source and compiled artifact, content digests, revision and profile/data-engine identities;
- module-scoped stable message keys, contract revision, descriptions, typed arguments, output kind, rich-markup contract, public visibility and override permissions;
- source/translation/review digests, stale detection, check report, strict review, merge without implicit prune, pseudolocales;
- `rain-mf2/v1`: multiple/nested selectors, cardinal/ordinal plural, exact number/string selection, typed format functions, local declarations and allowlisted rich markup;
- exact values and standalone formatters for number/money/percent/unit/date/instant/time/datetime/ranges/list/relative/duration/display names;
- BCP-47 negotiation with weighted `Accept-Language`, `q=0`, wildcards, lookup/best-fit choice, explicit parent graph, source provenance and independent template fallback;
- immutable `CatalogSnapshot`, typed deferred `Message`, generated Kotlin contracts, structural safe `RichParts`, render key and redacted explanation;
- allowlisted localization of existing `Fault`/`Violation` output without changing code, status, JSON pointer, partial flag, retry semantics or internal-error redaction;
- application and tenant whole-message overlays with strict higher-layer ordering, review/source/contract identity, audit and cache-generation fencing;
- process-local activation/rollback controller with opaque-head CAS, bounded retention and finite pins; optional durable artifact/release/pin store and exact durable job context;
- canonical public TypeScript type/manifest export with content-addressed, crash-safe multi-file publication; it does not claim JavaScript formatter parity;
- Kotlin usage extraction/checking through the K2 compiler-plugin resolved-IR API, generated Kotlin API, Gradle tasks, deterministic offline operation and full tests.

В состав входят и полные точки расширения для внешней TMS, remote artifact storage/watcher/polling, browser formatter и tenant-admin UI: `TranslationManagementConnector`, `CatalogReleaseSource`, `CatalogReleaseSink`, `ClientCatalogContract` и `TenantCatalogAdministration`. Для них поставляются SPI, модели команд/событий, authorization boundaries, conformance fixtures и deterministic in-memory adapters. Конкретный SaaS/vendor и конкретный web application остаются выбором продукта, а не скрытым или отсутствующим функционалом платформы.

## 3. Непереговорные инварианты

I1. Importing `rain-core`, `rain-web`, `rain-tenancy` or any transport does not introduce ICU4J or a catalog dependency. I18n is opt-in.

I2. A human message is `(qualified key, contract revision, contract digest, typed arguments)`, never a raw map or a locale-specific String passed through business code.

I3. A locale resolution, formatting locale, zone, presentation policy and catalog snapshot are explicit immutable view inputs. `Locale.setDefault`, `TimeZone.setDefault`, process-global mutable message maps and implicit first-request compilation are forbidden.

I4. Locale negotiation and template fallback are separate. The response records both resolved requested locale and actual template locale; a fallback is observable, never a silently guessed success.

I5. Source wording/description change invalidates translation review even when the typed message contract did not change. Contract change invalidates generated bindings and every incompatible translation/override.

I6. Every source, artifact, header, locale range, template, selector, value, output, explanation, generated file, publication and retained snapshot is bounded before proportional allocation or parsing.

I7. Plain rendered text is not HTML. Rich output is a safe typed part tree; translations cannot add attributes, arbitrary tags, scriptable links or unreviewed bidi controls.

I8. `FaultKind`, registered `ErrorCode`, HTTP status, `Violation.pointer`, `partial`, `Retry-After` and internal redaction are machine contracts. Localization can change only human text.

I9. An application/tenant override changes a whole translation only when the descriptor permits that exact layer and its locale, source digest, review digest and contract revision match. An overlay never changes argument schema, output kind, markup allowlist, public bit or key.

I10. A publisher activates one fully validated snapshot through opaque-head CAS. A stale A→B→A publisher cannot win. Failed activation/rollback leaves current snapshot unchanged.

I11. `PINNED_SNAPSHOT` durable delivery never renders a queued message with a newer release; unavailable pinned data is a typed closed failure, not fallback to current. `CURRENT_AT_RENDER` is explicit alternative semantics.

I12. Tenant locale/overlays affect presentation only. They cannot alter tenancy resolution, tenant authority, lifecycle, RLS, routing, admission, code/status/pointer or global Spring state.

I13. A digest establishes integrity, not provenance. A remotely obtained artifact is eligible only under an explicit trust policy and after detached signature verification against an active key id/algorithm; an artifact never becomes trusted merely because a remote endpoint supplied a self-consistent digest.

I14. For durable release mode, immutable release, head update, audit record and change-feed outbox are one transaction. Database head is authoritative; a node installs or invalidates a cache only from committed data. Push/listen notification is advisory and a lost notification is repaired by bounded cursor catch-up.

I15. ICU4J is the sole locale, Unicode and time-zone-rendering backend. `java.time` supplies domain `Instant`/`LocalDate`/`ZoneId` values only. Artifact identity records the ICU/CLDR/tzdb identity; a node whose configured backend does not exactly match refuses activation/rendering rather than mix JDK and ICU time-zone results.

I16. Composition grows linearly: a bridge names exactly two bounded contexts and publishes/consumes their narrow stable contract. A workflow that uses jobs, i18n and events is composed from independent jobs↔i18n and jobs↔event packages/contracts; it never creates a three-way `rain-jobs-i18n-events` module, an ambient cross-context context object or an N-way adapter family.

### 4.1 Deliberate Kotlin/Spring implementation mapping — no Go mechanics

This bounded context ports semantics, not Go implementation shapes:

- kernel APIs are ordinary synchronous Kotlin functions over immutable `data class`/sealed values; they accept neither `context.Context` analogues nor `CoroutineContext`, and do not require `suspend`. Rendering/compilation are bounded deterministic CPU operations. Deadline, cancellation and interrupt handling live at the existing servlet/Gradle/JDBC/remote-I/O boundaries; an adapter checks the existing `RequestDeadline` before/after blocking work and never smuggles a request context into a `CatalogSnapshot`;
- `CatalogController` uses a short critical section under `ReentrantLock` for its compound active/retained/pin transition. The returned `CatalogHead` is a value token `(releaseRef, opaque monotonically increasing headVersion)`, not a Go pointer/owner identity. The JDBC store performs the equivalent `UPDATE ... WHERE scope=? AND head_version=?` inside `TransactionTemplate`; a revision/digest match alone can never satisfy an expected head or reopen ABA;
- canonical JSON uses Jackson Core streaming (`JsonFactory`/`JsonParser` with read constraints) plus handwritten schema descriptors. It rejects duplicate/unknown fields and bounds input while read. It never relies on `ObjectMapper` permissive data-class binding, Go `reflect`, a generic JSON tree or a hand-written byte scanner merely because a standard library lacks strict decoding;
- generated Kotlin is the primary bind path. The low-level path is an explicit type-safe `MessageDefinition`/argument DSL and Java-visible factory methods. There is no runtime `kotlin-reflect`, struct-tag convention or reflective data-class encoder in production rendering;
- the web filter puts an immutable `I18nRequestContext` in the servlet request attribute; `I18nRuntime` is exposed as a Spring `@RequestScope` proxy. A named `TaskDecorator`/explicit `I18nContextSnapshot` is the only propagation route for an application executor. `LocaleContextHolder` is touched solely by the documented legacy Spring bridge and always cleared; it is never Rain state;
- observability is an immutable core `I18nObserver` event value plus an optional Micrometer `MeterRegistry` adapter, not a callback carrying ambient request context. Persistence uses jOOQ plus existing Rain `TransactionTemplate`, `Clock` and audit patterns.

## 5. Catalog and source contracts

### 5.1 CatalogSpec

`CatalogSpec` is a complete immutable declaration:

- release revision; `profile=rain-mf2/v1`; parser/compiler engine id; authoritative ICU/CLDR/tzdb identity;
- source locale, default locale, supported locales, required locales, explicit fallback-parent edges, match mode and `defaultOnMiss` policy;
- default formatting zone and declared capabilities;
- finite `I18nLimits` and observer;
- ordered module declarations and approved application overrides.

`MessageSpec` has exact module/id/key, contract revision, source text, translator description, typed `ArgumentSpec`s, `OutputKind.PLAIN|RICH`, allowed markup names, `OverridePolicy.NONE|APPLICATION|TENANT`, `allowEmpty`, `public` and translations. Key shape is `module.message_name`, max bytes is a limit, duplicate/canonical collision is a refusal. Modules contribute ordinary immutable declarations; classpath discovery and static initializer registration are forbidden.

`CatalogCompiler.compile(source)` accepts an all-or-nothing declaration, collects deterministic structural problems, and returns no partial snapshot. It validates BCP-47 tags, supported/required membership, parent acyclicity/depth, key uniqueness, argument schemas, locale coverage, source/review identities, profile grammar, formatter capability, markup contract, bounds and overlays before traffic.

### 5.2 Identity and review

`MessageContractRef(key, revision, digest)` covers key, declared arguments, output kind, markup contract, override policy and public bit. `SourceDigest` additionally covers profile, canonical source locale, exact source wording and translator description. `ReviewDigest` covers source digest, canonical translation locale and exact translated text.

Translation states are `APPROVED`, `REQUIRED`, `REJECTED`; only approved translation enters a runtime snapshot. Required locale completeness is measured after permitted application overlays. Optional debt is emitted by check and becomes a failure only under `--strict`. A wording/context change cannot accidentally remain approved; a source/contract mismatch cannot be force-rendered at runtime.

### 5.3 Canonical artifacts

The authoritative source document is strict canonical JSON `rain.i18n.source/v1`; compiled runtime artifact is `rain.i18n.catalog/v1`. Decoders reject unknown/duplicate fields, trailing values, invalid UTF-8, noncanonical digests, unbounded depth/members/bytes and semantic inconsistencies. Encoder and decoder round-trip byte deterministically.

Compiled artifact includes schema/profile/engine/ICU/CLDR/tzdb identities, snapshot digest and effective limits. `CatalogLoader` applies local operator ceilings: artifact-declared limits may narrow but never widen local limits. Loading is offline only and validates the entire artifact before `CatalogSnapshot` becomes visible.

An optional `ArtifactEnvelope` is required by every remote `CatalogReleaseSource`: it carries a bounded origin descriptor, artifact digest, signing key id, algorithm and detached signature over the exact canonical artifact bytes and identity fields. `CatalogTrustPolicy.LOCAL_BUILD|SIGNED_REMOTE` selects permissible origin; key rotation accepts an explicitly bounded active/retiring key set and audits the verifying key. Signature, identity or trust-policy failure is a refusal before persistence, cache or activation—not a warning.

## 6. `rain-mf2/v1` and rendering

### 6.1 Stable grammar, not preview API

Rain implements a versioned parser → AST → validated compiled template pipeline. ICU4J supplies stable Unicode, plural, list, number, date/time, unit and display-name data, but does not parse/own Rain message semantics. `rain-mf2/v1` takes the full behavior of VV profile:

- pattern/select messages; multiple and nested selectors; exact selector keys; required catch-all variant;
- typed input/local declarations; cardinal/ordinal plural and plural range; string selection NFC comparison without output mutation;
- functions `string`, `number`, `integer`, `currency`, `percent`, `offset`, `date`, `time`, `datetime`, `unit`; literal allowlisted options only;
- local declarations, exact offset add/subtract, selector/function combinations only where the declared argument type permits them;
- `u:id` and `u:dir=ltr|rtl|auto|inherit` literal metadata; no variable universal options in v1;
- plain patterns and rich markup with declared tags only, bounded nesting and no attributes/options supplied by translators.

Unknown functions/options/selector keys/attributes, unsupported literals, missing other variant, literal operand where a typed value is required, grammar auto-detection and silent option downgrade are construction failures. New syntax is a new `rain-mf2/vN` profile and cannot reinterpret a v1 artifact.

### 6.2 Values and generated bindings

Closed `MessageValue` variants: `Text`, `Boolean`, signed `Long`, unsigned `UnsignedLong`, `BigInteger`, scale-preserving `BigDecimal`, `Money(amount,currency)`, `LocalDate`, `Instant`, declared enum and explicit `Null`. `UnsignedLong` is a Rain JVM value object constrained to `0..2^64-1`, with Kotlin `ULong` and Java `BigInteger`/string factories, so Java callers never depend on Kotlin unsigned-name mangling. `OptionalValue<T>` is sealed `Absent|Null|Present<T>` because missing and explicit null have different template semantics; it is not a pointer substitute. `Double`, platform-width implicit numeric values, arbitrary objects and `toString()` formatting are refused. Mutable caller inputs are copied before a deferred message leaves a call.

`MessageDefinition<A>` binds a `MessageContractRef` and typed encoder. Generated Kotlin is the production path:

```kotlin
val message: DeferredMessage = catalog.tasks.pending.bind(TasksPendingArgs(count = 21L))
val rendered: RenderedMessage = i18nRuntime.view.render(message)
```

`rainI18nGenerateKotlin` generates one `Catalog`, exact argument shape (a singleton value for zero-argument messages, otherwise a data class), enum wrappers, nullable/absent `OptionalValue<T>` and contract digest literals. In a Kotlin/JVM project the magic plugin adds that generated source to `main` and schedules it before `compileKotlin`; the task, package, directory and low-level generator remain directly selectable. Generated catalog assembly rejects a stale runtime artifact before first request. Manual `MessageDefinition` plus its typed argument DSL remains an explicit low-level escape hatch for dynamic integrations; it performs the same eager schema validation and has no reflection path.

### 6.3 View, parts and observability

`CatalogSnapshot.resolve(choices)` returns sealed `LocaleResolution`: actual supported locale, choice source, outcome/reason and bounded preference trace. `snapshot.view(ViewSpec)` pins resolution, formatting locale, IANA zone, presentation/bidi policy and snapshot. A resolution from another resolver/snapshot is refused.

`View.render(deferredMessage)` returns:

- `text`;
- structural `RichPart` tree (`TEXT`, `VALUE`, `MARKUP_OPEN`, `MARKUP_CLOSE`, `BIDI_ISOLATE`) and typed format subparts;
- actual template locale, resolved locale/source/reason, winning layer, snapshot revision/digest, contract ref and deterministic `renderKey`;
- terminal render outcome.

`renderKey` binds every output-affecting input and is only a cache key. `View.explain(message)` returns a bounded resolution/template-fallback trace without message text, value, principal or tenant. Observer metrics use closed operation/outcome/reason/count/duration only; no key, source text, arguments, locale input, tenant or cause becomes a metric label.

Automatic FSI/PDI isolation is default; `Presentation.NO_ISOLATION` is explicit. Untrusted value bidi controls are refused; authored translation may use only balanced/allowlisted direction controls. `PLAIN` text must still be escaped by HTML/JSON/URL/shell sink. `RICH` is never a `String` trusted as HTML.

## 7. Full direct formatting surface

Every `View` and standalone immutable `Formatter` provides the same bounded, synchronous and deterministic surface:

- number, number range, money, money range, percent, percent range, unit, unit range;
- cardinal/ordinal plural and plural-range selection;
- `LocalDate`, `Instant` date, time, datetime and all corresponding ranges;
- list, relative time, duration and display names;
- named immutable formatter registry for application policies.

Numeric options include grouping, sign, notation/compact display, digit range, significant digits, rounding mode, rounding increment, priority, trailing-zero display, currency display/sign and plural type. Invalid combinations fail before a backend formatter runs. Decimal scale is preserved for plural selection (`1` and `1.0` may differ); no conversion through binary float.

Date/time options include style, component fields, hour cycle, calendar versus instant semantics, time-zone name and matcher. `LocalDate` does not move through zone; `Instant` formats in view zone. ICU4J provides every localized zone/calendar decision, while `java.time` objects are converted only as domain inputs after zone-id validation. Range output retains `START|SHARED|END` source provenance instead of flattening endpoints. List/relative/duration/display-name APIs have closed enums and the same output/bidi bounds as template rendering. No mutable ICU formatter is shared across requests: compiled format plans are immutable and a backend formatter is confined to one render.

## 8. Locale resolution and Spring magic

### 8.1 Resolver policy

`LocaleResolutionSource` is an ordered registry with stable id. It returns absent, malformed or a plain candidate only; it cannot mint a `LocaleView`. Standard order is:

1. explicit route/query/cookie choice only when application declares its source and write policy;
2. authenticated profile preference;
3. complete weighted `Accept-Language` fields;
4. tenant default locale/time zone after a minted tenant scope exists;
5. application default.

All candidates are canonical BCP-47. Header handling supports repeated fields, q weights, q=0 exclusions and wildcard under byte/range limits. `LOOKUP` never expands generic `zh` into arbitrary `zh-Hans`/`zh-Hant`; `BEST_FIT` is an explicit ICU/CLDR-versioned policy. `defaultOnMiss` is declared—not an environment or JVM fallback. Malformed/oversized policy outcomes are typed and must follow route contract (`406` versus explicit default); no source may affect authorization or tenant resolution.

### 8.2 Servlet and MVC integration

`rain-i18n-web` resolves one immutable view after authentication/tenant resolution, writes an `I18nRequestContext` request attribute, and exposes it as a Spring `@RequestScope` `I18nRuntime` proxy. This is magic-first: controller/service code injects `I18nRuntime` or accepts `LocalizedMessage`, while `CatalogSnapshot.view(...)` remains the complete low-level API. It does not open DB transactions or mutate catalog/tenant configuration.

For Spring compatibility it supplies a `LocaleContextResolver`/`TimeZoneAwareLocaleContext` bridge and binds `LocaleContextHolder` only for the servlet dispatch. The filter restores/clears it on normal return, exception, async dispatch, cancellation and reused worker thread; no inheritable thread-local is enabled. The Rain i18n view, not `LocaleContextHolder`, is authoritative. A named Spring `TaskDecorator` or explicit `I18nContextSnapshot` propagates an immutable captured view to an application executor and clears it in `finally`; raw executors remain explicit.

Responses set `Content-Language` to actual template locale, never merely requested locale. `Vary: Accept-Language` appears only when protocol choice participated; explicit route/profile/tenant choices have their own cache policy. `Locale`, zone, catalog revision/digest and overlay revision join cache identity; they never become high-cardinality metric labels.

## 9. Errors and protocol contracts

`rain-i18n-web` contributes `LocalizedProblemMessages`: immutable allowlisted mappings from registered `ErrorCode` and declared field-label keys to `MessageDefinition`. Mapping declares every safe parameter conversion and currency; a code's arbitrary `Fault.message` is **not** treated as catalog template/key. Missing mapping, bad params, incompatible view or render error declines to Rain's existing safe English fallback.

`ProblemRenderer` keeps RFC 9457 v1 bytes/field order and machine fields. For a non-internal mapped fault it replaces only `detail` and `errors[].message`; it preserves `type`, title/status, `code`, pointer, partial and retry header. Internal faults always keep `the request failed` and no violation body. `Content-Language` reports real template locale. A `LocalizedFault`/`LocalizedViolation` explicit API is available to applications that need typed arguments; it cannot carry arbitrary maps or force localize an unregistered code.

The same adapter pattern applies to email, notification, gRPC and CLI: a deferred message is rendered from a supplied `View`; transport never independently renegotiates a later locale.

## 10. Tenant, jobs and durable delivery

### 10.1 Tenant adapter

`rain-tenancy-i18n` is an optional `TenantRuntimeTask` after authority but before service execution. It reads only declared `TenantSettings` keys (`i18n.default-locale`, `i18n.default-time-zone`, `i18n.overlay-version`) and builds a tenant view from a minted scope. A central route has no tenant overlay/default. Custom runtime tasks cannot replace the selected view with a foreign tenant's overlay.

Tenant translations live in `rain_tenancy_i18n.tenant_overlay` and `tenant_overlay_revision`: digest/epoch, catalog ref, locale, key, complete template, source/contract/review identities, reviewer/actor, state, audit operation and monotonic version. Command `tenant-i18n-override-set/review/activate/rollback` requires admin grant, expected version, OperationId/receipt and audit in one transaction. The same tenant-owned transaction writes `rain_tenancy_i18n.tenant_overlay_change` with a monotonic cursor; `TenantOverlayChangeFeed.readAfter(cursor,limit)` repairs missed invalidations from committed records. A tenant may override only descriptor-approved messages; bounds, grammar and safe markup are validated before activation. Cache keys contain tenant digest + epoch + catalog digest + overlay version. Restore/new epoch cannot reuse old overlay cache.

### 10.2 Release controller and persistence

`CatalogController` is an in-process implementation of full lifecycle: `current`, `activate(expectedHead,candidate)`, `rollback(expectedHead,target)`, `pin(ref,ttl)`, `release`, `prune`. `CatalogHead` is an opaque value token with a monotonic head version; in-memory transition uses a short `ReentrantLock` critical section and durable transition uses jOOQ/`TransactionTemplate` optimistic update. It has bounded active/retained bytes/count/pins/lifetime and injected `Clock`; no watcher/timer/thread is created.

`rain-i18n-persistence` provides the durable equivalent for a product that publishes artifacts outside a deployment. Its migration creates `i18n_artifact` (digest, bounded bytes, profile/data/engine identity and verified envelope), `i18n_release` (immutable ref, artifact digest, actor/audit), `i18n_head` (scope, release ref, row version), `i18n_retained_release` (expiry/reason), `i18n_pin` (owner, exact catalog release ref, expiry), `i18n_audit` and transactional `i18n_change` outbox (monotonic cursor, committed `HEAD_CHANGED|RELEASE_PRUNED`). A tenant overlay is pinned in the separate `tenancy ↔ i18n` adapter/store; this module does not model tenancy or create an i18n-jobs-tenancy composition. Rows have explicit schema/version and size ceilings; artifact bytes and trust envelope are verified before use. Artifact load/activate use CAS and validate the same local ceilings/profile identities before commit. With one explicit `CatalogReleaseScope`, auto-configuration supplies a replaceable short-transaction `CatalogSnapshotProvider` for the authoritative head; a product cache/change-feed subscriber may replace it, but scope is never inferred from request/job/tenant state. `CatalogChangeFeed.readAfter(cursor,limit)` is bounded and cursor-based: every node catches up from durable data at startup and after a gap; a PostgreSQL notification or remote push merely wakes this read, never carries authority. `i18n-status`, `i18n-activate`, `i18n-rollback`, `i18n-prune` are RainCommands with bounded output and exact targets. `CatalogReleaseSource`/`CatalogReleaseSink` and `TranslationManagementConnector` cover polling, remote storage/TMS exchange, readiness and source authorization; scheduling remains application-owned and there is no hidden watcher.

### 10.3 Durable jobs/outbox

`rain-i18n-jobs` offers two declared modes:

- `CURRENT_AT_RENDER`: job carries a deferred message and canonical recipient presentation preferences; handler resolves then-current allowed catalog. It is explicitly non-reproducible wording.
- `PINNED_SNAPSHOT`: enqueue transaction captures catalog ref, tenant overlay ref/version and `ViewSpec`; durable pin retention covers retry/dead-letter/redrive horizon. Handler loads exactly that release/overlay or returns `i18n_snapshot_unavailable`; it never silently upgrades or falls back.

Context carries no raw tenant id, source text or unbounded arguments. Tenant jobs revalidate minted tenant scope/epoch before obtaining the tenant overlay. Pin release occurs only after terminal durable receipt; sweep is bounded and never deletes a referenced artifact. If the application stages a localized email via outbox, it chooses whether to stage rendered bytes or typed pinned intent; both contracts are documented and tested.

## 11. Authoring, extraction and public export

`rain-i18n-tool` is a Kotlin CLI plus Gradle plugin. Every producer is deterministic and bounded; Gradle cancellation is observed at task/I/O boundaries. Writers use Java NIO staging, `FileChannel.force(true)` and `Files.move(..., ATOMIC_MOVE)` in the same directory; an unavailable atomic move is a refusal, not a silent downgrade. Mutating writers use one descriptor-validated non-symlink `FileChannel` lock; `--check` is strictly read-only.

Commands/tasks:

| CLI | Gradle task | Contract |
|---|---|---|
| `check` | `rainI18nCheck` | source/translation/review/coverage/usage report, strict option |
| `extract` | `rainI18nExtract` | Kotlin/Java usage manifest, exact/bounded dynamic keys, completeness evidence |
| `merge` | `rainI18nMerge` | carry structurally eligible work; explicit `--prune-obsolete` only |
| `review` | `rainI18nReview` | stamp approved/rejected review identity |
| `pseudo` | `rainI18nPseudo` | accent and RTL pseudo locales without corrupting grammar |
| `compile` | `rainI18nCompile` | canonical runtime artifact |
| `generate-kotlin` | `rainI18nGenerateKotlin` | typed generated source/contracts |
| `export-typescript` | `rainI18nExportTypescript` | public-only branded type and manifest/pointer generation |

Extraction uses a packaged K2 compiler plugin at the pinned Kotlin compiler version, not KSP or a separately-distributed Analysis API: KSP cannot inspect resolved expressions/statements needed to prove `bind` calls or recognize callback escape, while Kotlin does not publish a stable standalone Analysis API artifact for this Gradle integration. The compiler plugin receives resolved IR without initializing application code. Its Gradle adapter writes one bounded atomic manifest per Kotlin compilation and its direct `-Xplugin` options remain available outside Gradle. It records exact resolved keys and source locations; dynamic operands and generated-binder callable-reference escape downgrade `complete=false`, and a release cannot claim a key is unused from incomplete evidence. Source-set/classpath/toolchain provenance is kept in the Gradle compilation boundary rather than copied into a cross-context application API; Java stays an explicit conservative lexical boundary until it receives its own semantic frontend.

Generated Kotlin is the canonical contract: catalog source is authoritative and Gradle adds generated sources before `compileKotlin`. This produces stable API for library consumers without annotation discovery. A packaged KSP declaration frontend may generate only the same declarations from a validated compiled artifact; it is optional ergonomics, has the same conformance fixtures, and can never replace canonical generation or K2 usage analysis.

TypeScript export includes only `public=true` messages, exact branded wire values and contract metadata. It explicitly declares `formattingParity=false`; browser rendering is a separately versioned client concern. Publication writes immutable `generations/sha256-.../messages.d.ts` and `messages.public.json`, then one verified `current.json` pointer. Reader pins pointer once and verifies fixed role/name/size/digest; retention is bounded and never races pins. Linked paths, unexpected files, pointer races and digest mismatch are refusals.
